# SecureVNC – Roadmap

Planned work, in the intended order. Done so far: item 0, phase A (1.5.0).

## Features

### 0. "Request help" from the tray icon
For colleagues who find computers hard: they ask for help with one click, the administrator's viewer shows it.

- **On the controlled computer:** right-click or double-click the tray icon → **Request help**, optional one-line description, **Send**, confirmation "An administrator will connect". The window runs as SYSTEM, so it has a text field only (no file dialogs, no links).
- **In the viewer:** can stay in the tray and listen; a notification "PC-05 (ivan) asks for help: …" with a **Connect** button, plus a list of recent requests.
- **Security (the request is a notice, never access):**
  - the request is **signed with the computer's certificate key** (computer name, Windows user, address, time, text);
  - the viewer shows it only if the certificate chains to a trusted CA (organization CA or pinned), the name matches, and it is fresh (about 2 minutes) and not a repeat;
  - **Connect** goes to the computer named in the certificate, never to an address taken from the message;
  - logging in is unchanged (password + code + ticket). Fake requests are impossible without the computer's key, and even a fake one could not reveal a password;
  - rate limit per computer against spam.
- **Phase A – done in 1.5.0:** signed UDP broadcast on the local network. Works in local and central mode; same network only; the viewer needs an inbound UDP firewall rule.
- **Phase B (with WireGuard, item 3):** requests delivered through the Auth Server over the computer's authenticated connection. Works across subnets and VPN, keeps a queue while viewers are off, every request in the audit; the viewer logs in to an administrator "inbox".
- Size: phase A medium; phase B medium to large.

### 1. Monitor selection
- Today the viewer shows the whole desktop (all monitors together).
- Viewer menu: **Monitor 1 / Monitor 2 / … / All**; mouse input mapped to the chosen monitor.
- Size: small.

### 2. Picture encoding choice (+ faster capture)
- Today: lossless zlib per rectangle – ideal on a LAN, heavy over the internet.
- Selectable modes: **lossless** (current), **JPEG with quality setting**, **16-bit colour**, **H.264 video** (optionally hardware accelerated), **frame-rate limit**.
- Screen capture via **DXGI Desktop Duplication** instead of GDI.
- Needed before item 3 (remote access over slow links).
- Size: JPEG and mode selection medium; H.264 large.

### 3. Access from anywhere with WireGuard
- SecureVNC stays as it is (TLS, MFA, tickets); **WireGuard adds an independent network tunnel** on top. SecureVNC ports are never exposed to the internet.
- A WireGuard hub with a public address (the Auth Server behind a port forward, or a small VPS).
- Every computer and every viewer gets its own WireGuard key; the **Auth Console generates the configurations** (and QR codes for laptops).
- Options being considered:
  - embedded WireGuard (wireguard-nt) – one installer, managed from the Auth Console (mind the GPL licence of the driver when distributing);
  - the official WireGuard client plus configurations generated by SecureVNC;
  - Headscale (free, self-hosted, Tailscale-compatible) for NAT traversal without port forwarding.
- Size: large.

### 4. File transfer with rules
- Through the same encrypted connection (no extra port); drag and drop in the viewer, both directions.
- **Rules in the Auth Console:** which administrator may transfer, in which direction, maximum size.
- **Every file in the audit** (who, name, size, hash, which computer); a notification on the controlled computer.
- Size: medium to large.

## Security hardening

| Item | What it adds |
|---|---|
| **CA key in the TPM** of the Auth Server | The key cannot be copied, even by an administrator of a running server |
| **FIDO2 security keys** (e.g. YubiKey) as second factor | A compromised Auth Server cannot forge the second factor (it keeps only public keys) |
| **Backup and restore of the Auth Server** (password-protected) | Recovery on new hardware without re-joining every computer |
| **Separate ticket-signing key** | Ticket signing and certificate issuing do not share one key |
| **Audit copy on another machine** (e.g. syslog / SIEM) | An attacker on the Auth Server cannot erase the traces |
| **Code signing** of the released files | No SmartScreen warning; tampered files are detected |
| **Smaller installer** | Auth Server and Server parts share one .NET runtime |

## Smaller improvements

- Clipboard sharing (with the same rules as file transfer).
